# 对局列表、事件与实时同步

`GET /api/games?page=0&size=20` 查询当前用户的对局。`page` 从 0 开始，`size` 为 1–100，结果按更新时间、ID 倒序排列。浏览器通过“加载更多对局”继续读取历史。

私有与公开回放均使用正向事件游标：

```text
GET /api/games/{gameId}/replay?afterSequence=0&limit=500
GET /api/public/games/{gameId}/replay?afterSequence=0&limit=500
```

`afterSequence=0` 从最早事件开始读取；之后将上一页最后一条的 `sequenceNo` 作为下一页的 `afterSequence`。每页最多 500 条，结果按序号升序排列，读到不足一页或空页时完成同步。此行为修正了旧版本中游标为 0 时返回最近一页的问题；直接调用 API 的客户端升级时应检查这一变化。

浏览器的观战页和复盘页会逐页读取完整历史。摘要的事件总数与淘汰次数由数据库计数，赛事投影和高光使用完整事件日志，不再以最近 5,000 条作为整场数据。

SSE 负责通知状态发生变化，持久化回放负责补齐历史。每次实时连接打开或重连成功，浏览器都会重新读取最新状态和缺失事件；即使断线期间对局已经结束，也会同步最终结算。多个事件触发的读取会合并并串行执行。

自定义模型端点仍需要精确主机白名单和有效的 HTTPS 证书。远程模型传输在建立连接时检查 DNS 结果并直接连接通过检查的地址，TLS 仍校验原始域名；本机、私网、保留地址、重定向和跨主机请求均被拒绝。

## 回归验证

`npm run test:e2e:functional` 覆盖桌面与移动端的长历史分页、断线结算恢复和旧对局翻页。`npm run test:e2e:visual` 同时检查 3D 舞台调整尺寸后的重绘。减少动效或低功耗模式下，画布调整尺寸后也会主动重绘。

CI 在 Linux 执行后端、MySQL 迁移与浏览器功能测试，在 Windows 执行视觉回归，以保持截图比较的平台一致。修改视觉基线前应检查实际差异。
